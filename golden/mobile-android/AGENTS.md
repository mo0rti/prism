# Android App - Prism Golden

## The slice

The pack generates one vertical slice and no example business features. Paths are under `app/src/main/kotlin/com/example/prismgolden/mobileandroid/`:

- `ui/signin/` is the screen labelled "Local development sign-in": `SignInScreen` (stateless), `SignInRoute` and `SignInViewModel`. Signing in calls the contract's `createDevToken` and opens the session.
- `ui/profile/` shows the signed-in user from `GET /api/me` (`getMe`): `ProfileScreen`, `ProfileRoute` and `ProfileViewModel`. A rejected token closes the session and returns to the sign-in.
- `ui/AppRoot.kt` shows the profile while a session is open and the sign-in otherwise.
- `data/api/` is the client of `shared/api-contracts/openapi.yml`: `ApiService` (Retrofit), `ApiModels.kt` (the DTOs), `ApiClient` (the interface the ViewModels use) and `RetrofitApiClient`.
- `session/SessionStore.kt` keeps the access token in memory only.
- `AppContainer.kt` wires the app by hand; `App.kt` owns it and `MainActivity.kt` hosts the Compose content.
- `designsystem/` holds `AppTheme`, `Spacing`, `LoadingIndicator` and `ErrorView`.
- `app/src/test/` holds the JVM tests: both ViewModels against `support/FakeApiClient`, the Retrofit client against a MockWebServer, `ApiContractTest` (the client against the contract) and `SignInScreenTest` (a Compose UI test under Robolectric that checks the "Local development sign-in" label).

## The dev identity is not authentication

The sign-in is the backend's local development identity. The backend serves it only under its `local` profile and only to requests that arrive from its own loopback interface, so a deployed backend answers 404 and the sign-in fails closed. It proves nothing about who the person is. Never present it as complete authentication, and do not ship it. The real identity provider, the authorization policy and the secrets are the project's own: replace the sign-in with the provider before anything ships (the `security-auth` and `android-conventions` skills describe how).

## Reaching the local backend

The backend accepts the dev identity from loopback only, so the app calls `http://localhost:8080/` (`apiBaseUrl` in `gradle.properties`, the backend this app was generated for) and `adb reverse` carries that to the host:

- **Emulator or USB device**: start the backend under its `local` profile, then run `task mobile-android:reverse` (`adb reverse tcp:8080 tcp:8080`) and open the app. Run it again after the emulator or device restarts or the adb server restarts.
- **Another backend port**: `task mobile-android:reverse BACKEND_PORT=<port>` and build with `-PapiBaseUrl=http://localhost:<port>/`.
- **A device on the network (Wi-Fi, no adb)**: the dev identity is not reachable and the sign-in reports it. Use `adb reverse` over USB or wireless debugging, or replace the sign-in with a real identity provider.
- Never use `10.0.2.2` or a LAN address, and never loosen the backend's loopback check or add a forwarding header to make a request pass. Debug builds allow cleartext HTTP to `localhost` only (`app/src/debug/res/xml/network_security_config.xml`); release builds are HTTPS-only and refuse an `apiBaseUrl` that is not `https://`.

## Build & Run

- **Build the debug APK**: `./gradlew assembleDebug` (`gradlew.bat` on Windows) or `task mobile-android:build`
- **Unit tests**: `./gradlew testDebugUnitTest` or `task mobile-android:test`. They run on the JVM, the Compose UI test included, and need no emulator.
- **Lint**: `./gradlew lintDebug` or `task mobile-android:lint`
- **Install and run**: start an emulator or connect a device, `task mobile-android:reverse`, then `task mobile-android:install`
- Set `ANDROID_HOME` (or `sdk.dir` in the git-ignored `local.properties`) to an Android SDK with platform 36, and run Gradle on JDK 21.
- Versions come from `packs/versions.yml` of the Prism template: `gradle/libs.versions.toml` and `gradle/wrapper/gradle-wrapper.properties` read them.

## Critical Rules

### Forbidden Patterns

- Logging, printing or persisting the access token, and adding an HTTP logging interceptor (a request carries the token)
- Putting the token anywhere but `SessionStore`: no `SharedPreferences`, file, `Intent` extra, navigation argument or `toString()`
- Hand-written calls to contract paths: add the operation to `shared/api-contracts/openapi.yml`, then to `ApiService`, `ApiModels.kt` and `ApiClient`, and extend `ApiContractTest`
- Pointing `apiBaseUrl` at `10.0.2.2` or a LAN address, or weakening the backend's loopback guard to make the dev identity work
- Allowing cleartext HTTP in `src/main`; it belongs to `src/debug` and to `localhost` only
- Reading `audience` anywhere: it is not shown or enforced in this app

### Gotchas

- A ViewModel takes its `viewModelScope` when it is first used, so a ViewModel test creates it in `@Before`, after `MainDispatcherRule` has replaced the main dispatcher.
- `adb reverse` is lost when the device or the adb server restarts. A sign-in that reports the backend as unreachable usually needs `task mobile-android:reverse` again.
- Two Android apps of one workspace differ in `applicationId`, `namespace` and package directories (all `com.example.prismgolden.mobileandroid`-style, derived from the app ID); never copy one app's folder to make another, scaffold it with `prism app add`.
- Do not move a dependency to another major version of its pinned baseline by hand: the pins live in `packs/versions.yml`.

## Architecture

MVVM in a single `:app` module. State flows down as `StateFlow` and events flow up as explicit `onXxxClick()` methods.

```
mobile-android/
  app/src/main/kotlin/com/example/prismgolden/mobileandroid/
    ui/signin, ui/profile   - Route (ViewModel wiring), Screen (stateless), ViewModel with its UiState
    ui/AppRoot.kt           - chooses the screen from the session
    data/api/               - the client of the shared contract
    session/                - the in-memory session
    designsystem/           - theme, spacing and shared components
  app/src/test/             - JVM tests (ViewModels, client, contract, Compose UI)
  app/src/debug/            - the debug-only cleartext policy for localhost
```
