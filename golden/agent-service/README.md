# Agent Service

The AI agent service of Prism Golden: Python 3.12, FastAPI 0.142.2 and uv, generated by Prism's `python-agent-service` pack. Port 8200.

It **assists and never advises**: it answers questions about the signed-in user's own data by calling read-only tools that use that user's own token, and every response says so. This is a starting point, not a finished assistant. It holds one compiling slice with its tests:

- `GET /api/health` reports that the process is up. It is the only open route.
- `POST /api/assist` takes a question and runs one agent turn through a provider interface with one example tool, `get_my_profile`, a read of the backend's `GET /api/me` with the caller's token.
- The provider interface has two implementations: a deterministic **fake** (the default: tests, CI and local runs need no key) and a **Claude API** adapter.

The slice has no business tools. Build yours beside it with the `add-tool` skill.

## Requirements

- [uv](https://docs.astral.sh/uv/) 0.11.26 or newer (it installs Python 3.12 for you)
- A running backend of this workspace, to call `POST /api/assist` end to end

No credential of any kind is needed to install, test, evaluate or start the service. A model API key is needed only for `AGENT_PROVIDER=claude`.

## Run it locally

Start the workspace's backend under its `local` profile (`task db-up`, then the `dev` task of your backend, which listens on port 8080 by default), then:

```bash
task agent-service:dev
```

Without Task: `uv sync --locked`, then `AGENT_PROFILE=local uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8200` in `agent-service/` (PowerShell: `$env:AGENT_PROFILE = "local"`).

Get a development token from the backend, then ask a question:

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/dev-identity/token \
  -H "Content-Type: application/json" \
  -d '{"email": "ada@example.test", "displayName": "Ada"}' | sed -E 's/.*"accessToken":"([^"]+)".*/\1/')

curl -s -X POST http://localhost:8200/api/assist \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question": "Who am I signed in as?"}'
```

The answer names the profile the tool read from the backend. Without a token the service answers `401`. Tokens last 15 minutes and stop working when the backend restarts, because its signing key lives only in memory.

If your backend is not on port 8080, set `AGENT_BACKEND_BASE_URL` (a loopback URL under `local`).

## Authentication: no shared secret

The service accepts the bearer tokens of the backend's identity and holds no secret:

- **`AGENT_PROFILE=local`** verifies the tokens of the backend's local development identity against the public key the backend publishes at `GET /api/dev-identity/jwks` (the backend serves it under its own `local` profile, to loopback requests only). It is local development sign-in, not authentication.
- **Anywhere else**, set `AGENT_OIDC_ISSUER` and `AGENT_OIDC_AUDIENCE` to your identity provider's issuer and this API's audience (`AGENT_OIDC_JWKS_URI` is optional). The service verifies tokens against the issuer's keys.
- **The service refuses to start** with neither, or with the `local` profile next to a real issuer, and it has no dev-identity endpoint and no setting that turns authentication off.

Never enable the `local` profile on a shared or deployed environment. The `security-auth` skill describes how the backend's dev identity is replaced; this service switches to the same issuer in the same change.

## Model providers

| `AGENT_PROVIDER` | What it is |
| --- | --- |
| `fake` (default) | Deterministic, no network, no key. It answers questions about the signed-in profile |
| `claude` | The Claude API through Anthropic's SDK. The model ID is `AGENT_CLAUDE_MODEL` (default `claude-sonnet-5-5`); the key is read from `ANTHROPIC_API_KEY`. Startup fails when the key is missing, and never falls back to the fake |

Never commit a key. Tests and CI use only the fake provider.

## Safety rules

| Rule | Where it is enforced | Tested in |
| --- | --- | --- |
| The service assists and does not advise; every response says so | `app/safety/notice.py`, `app/routes/assist.py` | `tests/test_agent_turn.py` |
| Untrusted content is data, never instructions: the question and every tool result travel in envelopes, and the system prompt is a constant | `app/safety/untrusted.py`, `app/agent/turn.py`, `app/agent/prompts.py` | `tests/test_agent_turn.py` |
| Tools only read, with the caller's own token; the model picks no URL and no user | `app/tools/` | `tests/test_agent_turn.py` |
| Every tool call is logged with the user and request IDs | `app/safety/audit.py`, `app/agent/turn.py` | `tests/test_agent_turn.py` |
| A per-user request and token budget, in memory, with a clear `429` | `app/safety/budget.py`, `app/agent/service.py` | `tests/test_agent_turn.py` |
| No data of one user enters another user's request | `app/agent/service.py` (a context per request, no shared state) | `tests/test_agent_turn.py` |

The notice's wording is generic. Adapt it to your domain with the `agent-safety` skill.

## Tests, lint and evaluation

```bash
task agent-service:test        # pytest: unit, auth, contract and evaluation tests; no network, no key
task agent-service:lint        # ruff check and ruff format --check
task agent-service:typecheck   # mypy --strict
task agent-service:eval        # the evaluation cases with the fake provider (what CI runs)
task agent-service:eval-live   # on demand: the same cases against the Claude API; needs ANTHROPIC_API_KEY and costs money
```

The app's CI workflow, `.github/workflows/agent-service.yml`, runs the install (`uv sync --locked`), lint, typecheck, tests and the fake-provider evaluation on a clean runner with no secrets.

## Layout

```
app/          main.py (create_app), config.py, errors.py, models.py
  auth/       JWKS key provider, token verifier, fail-closed startup rules
  agent/      the turn, the system prompt, the per-request service
  providers/  interface, fake, Claude adapter
  tools/      the tool base class, the registry, get_my_profile
  safety/     untrusted-data envelopes, budget, audit log, notice
  routes/     health, assist
tests/        pytest suites and helpers
evals/        evaluation cases (cases/*.toml) and the runner (python -m evals.run)
openapi.yml   this service's own contract
```

See `docs/guide.md` for conventions and `AGENTS.md` for the rules agents follow.
