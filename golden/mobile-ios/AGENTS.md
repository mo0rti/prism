# iOS App - Prism Golden

iOS app (Swift 6.0 with strict concurrency, SwiftUI, iOS 17.0+, Xcode 26.0), generated by Prism's `ios-swiftui` pack at `mobile-ios/`. Building needs a Mac with Xcode; the macOS CI job of this app is what proves the build.

Treat Swift strict concurrency as the baseline:

- View models that drive SwiftUI state are `@MainActor @Observable`.
- Types that cross actors are `Sendable`; dependencies are injected through initializers at the composition root, `RootView`.
- Do not add `@unchecked Sendable` or `nonisolated` workarounds without a stated reason in the change.

## The slice

The pack generates one vertical slice and no example business features:

- `Sources/SignIn/SignInView.swift` is the screen labelled "Local development sign-in"; `Sources/SignIn/SignInViewModel.swift` asks the backend's local development identity (`POST /api/dev-identity/token` of `shared/api-contracts/openapi.yml`) for a token.
- `Sources/Profile/ProfileView.swift` shows `GET /api/me`; `Sources/Profile/ProfileViewModel.swift` reads it with the stored token and ends the session when the backend rejects the token.
- `Sources/Networking/APIClient.swift` is the client of the two contract operations. `Sources/Networking/APIEndpoint.swift` lists their paths, `Sources/Networking/APIURL.swift` joins the base URL and a path, and `Sources/Networking/APIError.swift` holds the errors the screens show.
- `Sources/Session/TokenStore.swift` keeps the token in memory. `Sources/Session/SessionModel.swift` says whether a person is signed in, and `Sources/RootView.swift` chooses the screen from it.
- `Sources/AppInfo.swift` reads the display name and the audience from `Sources/Info.plist`. The audience is display text only: no screen, check or permission reads it.
- `Tests/` holds the unit tests of both view models (with `Tests/Support/FakeAPIClient.swift.jinja`) and of the client; `UITests/SignInUITests.swift` is the UI test of the sign-in screen.
- `project.yml` defines the app target `MobileIos`, its test targets, the scheme `MobileIos` and `API_BASE_URL` per build configuration. The bundle identifier is `com.example.prismgolden.mobileios`.

## The dev identity is not authentication, and it works in the simulator only

The sign-in is a local development identity. The backend serves it only under its `local` profile and only to requests from its own machine (loopback), so a deployed backend answers 404 and the sign-in fails closed. The simulator shares the Mac's network, so `http://localhost:8080` (the Debug `API_BASE_URL`) reaches a backend on the Mac as loopback. A physical device is not on the backend's loopback and cannot use the dev identity: the backend refuses it with 403, and the app says so. Never present the sign-in as complete authentication, and do not ship it. The real identity provider, the authorization policy and the secrets are the project's own: replace the sign-in with the provider before anything ships (the `ios-contract-alignment` and `security-auth` skills describe how).

## Build & Run

- **Generate the project**: `task mobile-ios:generate-project` (or `xcodegen generate` in `mobile-ios`). The `.xcodeproj` is generated and git-ignored; `project.yml` is the source.
- **Build**: `task mobile-ios:build`
- **Test**: `task mobile-ios:test` (unit and UI), `task mobile-ios:test-unit`, `task mobile-ios:test-ui`
- **Run**: open `MobileIos.xcodeproj` in Xcode and run on a simulator, with a backend running under its `local` profile (`task db-up`, then `task <backend-app-id>:dev`)
- Tasks use `SIMULATOR_NAME` when it is set and the newest available iPhone simulator otherwise (`scripts/select-simulator.sh`).
- `API_BASE_URL` is set in `project.yml`: Debug is `http://localhost:8080`, Release is empty until you set your deployed backend. The Info.plist carries it, and `APIURL.configuredBaseURL()` reads it.

## Critical Rules

### Forbidden Patterns

- Hand-written requests to paths the contract lacks: add the operation to `shared/api-contracts/openapi.yml`, then to `Sources/Networking/APIEndpoint.swift` and `APIClient`
- Putting the token in a URL, a log, `print`, `UserDefaults`, an error message or a file
- Reading `audience` anywhere but the display text
- Secrets or tokens in the repository

### Gotchas

- The UI tests wait until an element is hittable and allow 30 seconds per screen, because simulators on CI runners are slow. Keep that when you add a UI test.
- Info.plist values come from build settings (`$(API_BASE_URL)`); change them in `project.yml` and regenerate, not in the generated project.
- App Transport Security allows plain HTTP to local networking only (`NSAllowsLocalNetworking`); a deployed backend must use HTTPS.
- Do not move a version off the pins of `packs/versions.yml` by hand: Swift, Xcode and the deployment target come from there.

## Architecture

```
mobile-ios/
  project.yml      - XcodeGen definition: targets, scheme, build settings
  Sources/         - the app: RootView, SignIn/, Profile/, Networking/, Session/, Models/, AppInfo
  Tests/           - XCTest unit tests and the fake API client
  UITests/         - the XCUITest of the sign-in screen
  fastlane/        - TestFlight lane (see the deployment skill); CI does not release
  scripts/         - simulator selection for the tasks
  docs/guide.md    - structure and commands
```
